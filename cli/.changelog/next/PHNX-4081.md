- **A launched agent's own `secrets` calls hit the store agents-cli reads for it (PHNX-4081).** `buildExecEnv` now exports `SECRETS_HOME` (the user agents dir, unless the launching environment set one), the same root the process client already passes the standalone. Before, an agent's `secrets exec` inside a Claude Code or Cursor session ran against a second broker under `~/.secrets` with its own event log, so an unlock in one store was invisible in the other. The pinned standalone moves to `@phnx-labs/secrets-cli@0.1.4`, whose broker keeps `--durable` unlocks across restarts and lets a user-driven agent raise the Touch ID sheet instead of asking for `secrets unlock` by hand. Source: `cli/src/lib/exec.ts`, `cli/src/commands/setup-secrets.ts`.
