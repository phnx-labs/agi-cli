- **`--device auto` no longer refuses a worker whose usage reading is merely old (PHNX-4116).**
  Remote readiness re-derived a 40-minute usage-freshness refusal from `agents view --json`'s
  per-version list, so one broken usage-sync made every worker read `no ready harness account`
  while `--device <name>` on the same box launched fine. The dispatcher now READS the running box's
  own `runReady` verdict instead of re-deriving it (see the readiness fragment); usage age weights
  the pick, it never decides eligibility. Source: `cli/src/lib/hosts/ready.ts`.
