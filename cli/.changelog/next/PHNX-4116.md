- **A daemon service that fails again after a backoff restart is restarted again instead of staying parked forever (PHNX-4116).**
  The supervisor never dropped the handle of a restart timer that had already fired, so the next
  deadline breach on that service read "a restart is already pending" and scheduled nothing.
  `daemon-heartbeat` and `usage-sync` sat parked for days on zion and four workers: the daemon
  reported `wedged`, no usage rows reached the fleet, every worker's Claude usage went stale past the
  40-minute routing window, and `agents run claude --device auto` refused every device with
  `no ready harness account`. Source: `cli/src/lib/daemon/supervisor.ts`.

- **`--device auto` no longer refuses a worker whose usage reading is merely old (PHNX-4116).**
  Remote readiness treated a Claude usage snapshot older than 40 minutes as "not ready", so one
  broken usage-sync made every worker read `no ready harness account` while `--device <name>` on the
  same box launched fine. A stale reading now leaves the account unverified (its throttle marker is
  not trusted, and the remote run weights it at the floor); only a fresh rate-limit or a fresh dead
  auth verdict excludes it. Source: `cli/src/lib/hosts/ready.ts`.
