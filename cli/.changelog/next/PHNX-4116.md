- **`--device auto` no longer refuses a worker whose usage reading is merely old (PHNX-4116).**
  Remote readiness treated a Claude usage snapshot older than 40 minutes as "not ready", so one
  broken usage-sync made every worker read `no ready harness account` while `--device <name>` on the
  same box launched fine. A stale reading now leaves the account unverified (its throttle marker is
  not trusted, and the remote run weights it at the floor); only a fresh rate-limit or a fresh dead
  auth verdict excludes it. Source: `cli/src/lib/hosts/ready.ts`.
