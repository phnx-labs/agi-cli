- **A first install no longer turns on hooks and auto-approved commands unless you choose them, and a no stays a no.** The interactive first-run prompt from `agents add <harness>` (and `agents sync` or `agents refresh` on a never-synced version) used to pre-select every resource, including the system repo's hooks (scripts that run on every prompt and tool call, such as `main-branch-guard`, which refuses edits in your own checkout) and its permission groups (allow and deny rules that auto-approve commands such as `git push`, `ssh` and `curl`). Both now start unchecked and say what they do; commands, skills, rules, MCPs, subagents and plugins stay checked, and accepting the defaults is still one Enter with no per-category follow-up. Leaving hooks or permissions unpicked records it on that version (negated patterns such as `!system:*`), so a later sync never default-fills them back and the next `agents sync`, `agents add` or refresh does not offer them as new, and `agents doctor` no longer reports them missing, so its heal does not reinstall them; pick them later with `agents hooks` or `agents permissions`. "Select All" still opts into everything, and scripted runs (`--yes`, or no terminal) keep their full selection, so existing fleet setup is unchanged. Source: `cli/src/lib/installations/versions.ts`, `cli/src/lib/state.ts`, `cli/src/lib/doctor-diff.ts`.
