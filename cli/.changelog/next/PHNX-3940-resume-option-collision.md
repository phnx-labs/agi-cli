- **`sessions resume --device`/`-a`/`--all`/`--teams`/`--since`/`-n` now reach the resume subcommand instead of silently vanishing into the parent `sessions` command (PHNX-3940).** `sessions resume` declares several flags by the same name as its `sessions` parent; because `root-command.ts` cannot call `enablePositionalOptions()` globally (it breaks `sessions backfill …`'s `optsWithGlobals()` pattern), commander's parser consumes a colliding flag typed anywhere on the line into the PARENT's own option before `resume` is even recognized as a subcommand — so `agents sessions resume <id> "<prompt>" --device <box> --tmux` silently dropped `--device` and attempted a local tmux launch instead of routing to the named device. `resolveResumeOptions` (`cli/src/commands/sessions-resume.ts`) recovers the caller's real intent: an explicit parent-level value overrides the resume subcommand's own default (so a bare `sessions resume` still keeps its 200-row default instead of inheriting the parent's 50), and `--device`/`--devices` are merged and collapsed to exactly one device via a new shared `normalizeSingleDeviceOption` (`cli/src/commands/utils.ts`, factored out of `sessions inject`'s existing single-device coercion), failing loud on more than one rather than guessing. Source: `cli/src/commands/sessions-resume.ts`, `cli/src/commands/utils.ts`, `cli/src/commands/sessions-inject.ts`.
