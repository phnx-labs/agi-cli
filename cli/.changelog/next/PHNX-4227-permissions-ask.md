- **A permission preset that names a missing group fails, and `ask:` rules sync into harnesses that can prompt on a rule (PHNX-4227).** `buildPermissionsFromGroups` used to skip a group whose file was not there, and preset sync dropped missing includes before that function ran, so a dangling name such as `16-mcp` disappeared. A named group with no `permissions/groups/<name>.yaml` now throws, and the error names the active preset and the group. `00-local` stays the one optional per-machine group and is skipped when its file is absent. An `ask:` section is kept beside allow and deny. It is written to the native prompt list where one exists: Claude `permissions.ask`, OpenCode `permission.bash` value `ask`, Codex `agents-ask.rules` (`decision = "prompt"`), Grok `action = "ask"`, Kimi `decision = "ask"`, Droid `permissionRules` decision `ask` (not `commandDenylist`), and Antigravity `permissions.ask`. Cursor, Copilot, OpenClaw, and Hermes have no per-rule ask list. Allow and deny still sync, and the ask rules are skipped with the reason recorded on `PERMISSION_TARGETS`. Source: `cli/src/lib/permissions.ts`, `cli/src/lib/permissions-registry.ts`, `cli/src/lib/installations/versions.ts`.
