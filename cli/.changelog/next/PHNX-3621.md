- **The session index now persists `firstUserMessage` — the full genuine first user turn — and surfaces it on `sessions watch --json` (PHNX-3621).** A consumer that wants to show a session's real opening prompt (the AGI EXT Sessions "THE ASK" line) previously had only `topic` (a truncated first-line summary), `label` (an agent/user-set title), or a live-row `userPromptClean` (a display-cleaned turn) — none of them the actual full prompt, and none available without re-reading the transcript. Every harness scanner that can locate a first user turn now captures it verbatim at scan time (claude/codex resumable-state parsers, gemini/rush/hermes/muse/droid/antigravity/cursor/kimi/grok/opencode), persists it in `sessions.first_user_message`, and reads it back into `SessionMeta.firstUserMessage`. Running `--active` rows and the canonical `SessionWatchRow` are backfilled from the index exactly like `version`/`account`, so the watch stream carries the real prompt with **no side-channel fetch**. Additive and backward-compatible: old rows read the field as absent and re-derive it on their next scan (paired `CONTENT_INDEX_VERSION` bump). OpenClaw is out of scope — its index rows are a live channel/cron inventory with no transcript. Source: `cli/src/lib/session/discover.ts`, `cli/src/lib/session/db.ts`, `cli/src/lib/session/active.ts`, `cli/src/lib/session/remote/watch.ts`, `cli/src/lib/session/types.ts`.
- **`sessions watch --json` / `feed watch --json` now carry durable "Previous" rows, so a consumer's recoverable-history list needs no side-channel fleet sweep (PHNX-3621).** The stream previously emitted only the LIVE session cache; the AGI EXT Sessions panel filled in prior sessions with its own `fetchPreviousSessions` sweep, now deleted. The canonical CLI stream owner now folds a bounded set of this device's own resumable sessions from the transcript index — last 7 days, at most 50, team-origin / archived / synthetic rows and captured-only harnesses with no native resume path (gemini/antigravity/grok/kimi/droid/cursor/rush/hermes/openclaw) excluded, so the recoverable-history stream never carries a row whose Resume would dead-end — into the reset and every delta beside the live rows. Each Previous row (`previous: true`) carries `recovery`, `sourceDevice`, the exact `harness`, `firstUserMessage`, and the CLI-derived `phase`/attention the extension reads. A live row wins by session id, and the set is re-derived on the same journal/index publication seam the live snapshot rides (never a consumer poll), so a just-ended session transitions in place from its live row to its durable Previous row. Source: `cli/src/lib/session/remote/watch.ts` (`buildPreviousRows`, `watchLocalSessions`), `cli/src/lib/session/resume-capability.ts` (`isResumableHarness`, the one predicate shared with the SessionPicker projection and `buildResumeCommand`), `cli/src/lib/session/active.ts`.
