- **`agents fork <id> --device <box>` works again, and so does every other command that declares its own `--device`.** The fleet router rejected `--device` on any top-level name missing from its hand-kept list, so `agents fork`, `agents cloud run`, `agents projects status` and `agents projects pull` all failed with "does not support --device". The router now steps aside whenever the resolved command declares the routing flag itself, and a test walks the whole command tree so a moved or new command cannot lose `--device` silently. `agents config list --device <name>` now runs its own handler (that device's config read here) instead of being forwarded to the device; `agents repos list|status --devices all` uses the command's own fleet report instead of the router's fan-out, and `agents routines add --devices all` now fails with "Unknown device(s): all" instead of adding the routine on every device. The fork sibling starts in the source session's folder (`--cwd`) when it lands on a device or the source is on this machine, and `agents ps preview` exits 1 when the hop to the owning device fails, so `agents fork` reports the peer's error instead of "could not read the source". Source: `cli/src/lib/hosts/routing-flag.ts`, `cli/src/lib/hosts/passthrough.ts`, `cli/src/commands/fork.ts`, `cli/src/commands/ps.ts`.
