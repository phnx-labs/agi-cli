- **Interactive Claude runs on a worker fail loud instead of dropping to the login screen (PHNX-3502 sibling).** `agents run claude --interactive --device auto/<worker>` whose selected account had no synced setup-token used to fall through to Claude Code's "Select login method" screen — an interactive OAuth on a headless box that never persists, so Anthropic re-prompted on the next run (the repeated re-login loop). The run is now refused before spawn with the real fix (pin a live account with `agents run claude#<name>`, set the fleet default with `agents accounts default claude <name>`, or mint the account's token on a headed box with `agents accounts login claude#<name>`). Headless runs are unchanged (they already fail loud with a 401), and headed boxes still show their normal native-login prompt. Source: `cli/src/lib/harness/adapters/claude.ts`, `cli/src/lib/exec.ts`.

- **`agents view` and `agents accounts list` read as name + usage (PHNX-4051).** The
  account table printed IDENTITY, STATE and WHERE on every row — an email, `UNVERIFIED`
  and `on 9 boxes` repeated down the whole list — which pushed the usage bars past the
  terminal width and wrapped every line. A row is now the account name and its usage
  bars, and nothing else when the account is healthy. Only a state worth acting on
  trails the row: `rate-limited` (yellow), `expired` / `revoked` / `missing` (red),
  partial fleet coverage (`usable on 3 of 5 boxes`), then the repair command. A
  blocking marker (`out of credits`) now renders after the bars instead of in front of
  them, so one throttled account no longer misaligns the table, and a stale window is
  `48%* (period ended 2h)` rather than `48% · stale (period ended 2h ago)`. The identity
  and per-device state the columns carried are still one command away —
  `agents accounts list --fleet`, `agents accounts view <name>`, `--json`. A discovered
  login nobody has named is listed by its identity (the email) rather than `unnamed`. Source:
  `cli/src/lib/account-catalog.ts`, `cli/src/lib/accounting/usage.ts`,
  `cli/src/commands/view.ts`, `cli/src/commands/accounts.ts`.

- **`agents computer` now uses the standalone `computer` CLI (PHNX-4075).** Install it with `npm i -g @phnx-labs/computer-cli`; `agents setup computer` also installs it when missing. The standalone package owns desktop commands, native helpers, remote provisioning, and VNC transport. Agents retains fleet device resolution, permission groups, session identity, and action history. The separate `computer` npm executable and native helper sources now ship from the standalone project.
- **Release cleanup preserves unfinished work.** Dirty orchestration, publication, and attestation worktrees remain available with their paths printed. Generated files are restored only after their exact contents are saved in the release PR head; later edits are preserved.

- **A launched agent's own `secrets` calls hit the store agents-cli reads for it (PHNX-4081).** `buildExecEnv` now exports `SECRETS_HOME` (the user agents dir, unless the launching environment set one), the same root the process client already passes the standalone. Before, an agent's `secrets exec` inside a Claude Code or Cursor session ran against a second broker under `~/.secrets` with its own event log, so an unlock in one store was invisible in the other. The pinned standalone moves to `@phnx-labs/secrets-cli@0.1.4`, whose broker keeps `--durable` unlocks across restarts and lets a user-driven agent raise the Touch ID sheet instead of asking for `secrets unlock` by hand. Source: `cli/src/lib/exec.ts`, `cli/src/commands/setup-secrets.ts`.

- **One fewer cold `secrets` process on every command that touches secrets (PHNX-4082).** Each synchronous secrets request spawns a fresh `secrets __serve`, so it pays a full Node boot of the standalone — 0.3–2.6 s on a desktop at load average ~100. The client spent one of those purely to ask which protocol version the standalone speaks, before the first real request of every process. It no longer does: every response envelope already carries `v`, and `parseResponse` checks it on each one. That is also stricter than the handshake it replaces — a standalone that answered the handshake as v1 and a later op as v2 used to surface as "malformed response envelope" and now reports `secrets speaks protocol 2; this agents-cli needs 1`. Measured on `agents run claude`: 7 standalone spawns before, 6 after. Source: `cli/src/lib/secrets-client.ts`, `cli/src/lib/secrets-client.test.ts`, `cli/docs/secrets-client.md`, `cli/docs/specifications.md`.
